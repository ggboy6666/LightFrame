# 轻帧 LightFrame 0.2.4 测试版

原生 Android 性能记录工具。0.2.4 修复手机 / 平板图表的文字和比例，补充纵轴数字；排除无效窗口造成的伪 0 FPS；支持手动填写三类采样间隔；集中 Shizuku / Root 授权向导。历史支持准确时刻、起止区间、拖动缩放、原始数值和导出，全记录统计在停止录制后计算。浅紫色界面风格参照用户提供的 RakkaRecorder 录屏，程序为独立实现。

## 手机上使用

1. 停止旧记录，再安装 `LightFrame-0.2.4-beta.apk`，支持 Android 8.0 及以上。与之前的轻帧测试版签名一致，覆盖安装保留私有记录；不要先卸载。
2. 无 Root 时，在轻帧主页打开“采集授权向导”，检测、启动 Shizuku 并授权。Shizuku 的无线调试启动可在支持的手机上完成，轻帧日常使用不要求连接电脑。Sui 通过同一授权接口使用。
3. 已 Root 时可选“Root”；“自动选择”优先使用已授权的 Shizuku / Sui，再尝试 `su`，否则显示“基础模式”。基础模式的 FPS 等受限指标会显示未取得。
4. 按需授予悬浮窗和通知权限。填写记录名称，可填写游戏包名以减少自动选错图层的机会。
5. 可先在设置点击“应用低开销预设”：帧 250ms、硬件 1s、温度 5s，下一次记录生效。
6. 点击“开始记录”，进入游戏。结束后在悬浮通知或主页点击“停止并保存”，等待“已保存记录并完成统计”。录制时仅维持必要实时值与原始写入，Low、分位数和全记录摘要在停止后计算。

默认帧采样间隔 250ms、硬件间隔 1000ms、温度间隔 2000ms。设置页可手动填写整数毫秒，三项分别允许 50–5000、100–60000、500–60000ms，保存前会逐项检查；下一次记录生效。间隔小，读取次数、CPU 开销和文件量增加；间隔大，可能遗漏短时峰值，帧缓冲还可能出现缺口。温度通常更新较慢，过快读取常得到重复值。建议从帧 100–250ms、硬件 1000ms、温度 2000–5000ms 起步，按实际读取状态调整。接口耗时过长时自动放慢，不补跑积压任务。

悬浮窗支持 1–12 项指标选择，拖动移动、双击打开、长按隐藏；通知可暂停、显示/隐藏、停止保存。息屏时自动暂停，亮屏后继续。

## 查看每次的数值

- 在“记录”打开一条记录，在 FPS、CPU、频率、GPU、RAM、功耗、温度、电池标签查看曲线。
- “时间浏览 → 跳到准确时刻”支持录制经过秒数、`分:秒.毫秒`、`时:分:秒.毫秒`，或选择手机本地日期时间。显示最近实际采样以及时间差；没有该时刻的采样时不会插值造值。
- “选择起止区间”筛选曲线、采样明细和逐帧数据。“放大 + / 缩小 − / 全部”以及向前、向后半窗按钮便于精确浏览；所有指标共用同一个时间窗口。
- 点选曲线，底部显示最近的**原始采样时刻**、序号及该次全部指标。上一条 / 下一条精确移动一行，不沿合并后的曲线点跳转。
- “查看原始数值”显示 CSV 原始精度的所有列，可长按复制。
- “采样明细”每页 50 行，支持翻页和按序号跳转。点击行查看全部数值。
- “逐帧数据”按捕获帧顺序显示呈现时间、帧间隔及长帧标记，支持上一帧 / 下一帧。
- 曲线支持双指缩放、左右拖动、双击复位。长记录的曲线绘制使用分桶最小/最大值；原始 CSV 没有删减。所有摘要极值和均值都来自全量有效采样。
- “查看区间全部统计 / 缺失原因”显示区间内全量有效值的统计、缺失数量和原因。空区间明确提示；上一条 / 上一帧不会越出所选区间。
- 右上角导出完整 ZIP、完整或当前区间的采样 CSV / 逐帧 CSV、单条曲线 PNG。建议结束记录后导出完整结果；正在记录或后台分析时只读已落盘的快照，使用“刷新记录快照”更新。
- 旧记录打开时可从 CSV 恢复缺失或损坏的摘要。原始文件不改写，旧版采集错误或从未取得的 GPU 数值无法通过重算补回。

## 指标口径

| 指标 | 来源与含义 |
| --- | --- |
| FPS | SurfaceFlinger 指定图层的实际呈现时间；完整的近 1 秒呈现窗口内计算，首次进入或换源先显示“采样中”，避免按启动后时间累计造成假爬升。自动模式限定前台包归属，保留有效图层，避免周期换源。 |
| 帧时间 / 逐帧时间 | 捕获的相邻实际呈现时间差。SurfaceFlinger 缓冲或系统限制导致没捕获的帧无法还原。 |
| 1% / 0.1% Low | 停止后计算捕获间隔中最慢 1% / 0.1% 帧时间的均值倒数；常见范围为 0.5ms 直方图近似，极长间隔用更宽分桶。 |
| FPS P1 / P5 | 有效 FPS 采样值的第 1 / 5 百分位；0.5fps 分桶近似。与逐帧 Low 是不同统计。 |
| FPS 波动 | 有效 FPS 采样值的标准差；不使用商业工具的“抖动率”名称。 |
| 长帧 / 严重长帧 | 超过设置的目标帧预算的 1.5 倍 / 3 倍的估算。与 Android 官方 Jank、PerfDog、RakkaRecorder 的口径不保证相同。 |
| CPU | `/proc/stat` 系统总体使用率；频率按 cpufreq policy 分组，最多 16 个策略，不把策略序号当成物理核心编号。 |
| GPU | 系统总负载，探测 Qualcomm KGSL、MediaTek GED（含 module gpu_loading）/ gpufreq、GPU devfreq 等只读节点；频率单位按节点格式转换。GED 驱动明确禁用时不把清零值作为真实负载。 |
| 温度 | 从明确的 CPU / GPU / SoC 热区取最高有效值；电池温度独立，绝不替代 CPU/GPU 温度。 |
| RAM | 系统 `MemTotal - MemAvailable`，不是目标游戏的独占内存。 |
| 电流 / 功率 | 电池接口电流（mA）和电压（mV），功率为绝对电流乘电压。是电池侧估算，充电时不代表设备总输入功率，也不是 CPU/GPU 芯片功耗。 |
| 网络 | 所有非 lo 接口的收发汇总；VPN 等场景可能重复计入。 |
| 轻帧 CPU / RSS | 应用与独立采集进程之和，CPU 为单核当量；RSS 可能重复计算共享页。不含 Shizuku 管理器、系统执行采集请求的开销和 GPU 绘制。PSS 只在手动诊断时获取。 |
| 数据距今 | 硬件与温度的采集年龄（ms），用于识别快采样中重复显示的较慢指标。 |

读不到的指标显示 `—`；GPU 被拒绝读取时，实时页面和悬浮窗显示“读取受限”，驱动禁用时显示“接口未启用”。CSV 对应空白，绝不自动补成 0。真实的 0 使用率仍保存为 0。游戏更换图层、暂停或息屏后会清除时间基线并拒绝旧缓冲。若有限的 SurfaceFlinger 缓冲未衔接，分段记录并重建窗口，不把缺失时间伪造为一条长帧；请按读取状态适当减小帧采样间隔。

曲线按当前窗口尺寸绘制，支持手机、横屏、平板和分屏；文字不会随图表宽高非等比拉伸。CPU / GPU 百分比轴为 0–100%，越界原始值会标记；FPS 和轻帧单核当量 CPU 轴覆盖实际峰值。无效、过期窗口的 FPS 显示为空，不进入均值或最低值；真实低帧数和逐帧长卡顿仍保留。旧记录只有同一行明确证明窗口无效时才排除 0，证据不足的旧 0 保留，原始 CSV 不改写。

## vivo / 联发科适配

用户此次 vivo PA2573 / Android 16 日志已确认 Shizuku 采集 UID 为 2000，已探测的 GED、gpufreq、Mali 节点，包括新增 module gpu_loading，均无法获得 GPU 使用率和当前频率。用户确认没有 Root；0.2.4 保留权限受限提示，不依赖 Root 修复历史和 FPS。温度日志有 CPU / GPU / SoC 类型值，相同温度来自系统报告，不能认定为独立物理传感器。新版尚未安装到该手机，vivo 平板也未验证。

本版的手动诊断增加限时、限量的 Perfetto 数据源只读查询，仅报告可探测能力，不启动追踪，也不能宣称解除了 GPU 权限限制。内置无线 ADB 的可行性、首次配对限制与后续验证范围见 [授权方案](docs/ACCESS-OPTIONS.md)，本版未实现可用的内置无线 ADB 启动器。

GPU / 温度未取得时，在“设置 → 导出采集诊断”保存文件，其中有设备信息、读取权限、原始节点内容和图层。设置页可指定 GPU 频率、使用率、温度节点及固定图层。节点只接受 `/sys/` 或 `/proc/` 内路径；只读，不更改频率、温控或系统参数。自定义频率节点应为单值，使用率支持百分比首值或 `busy total` 两数格式；复杂厂商格式需要修改对应解析器。

## 开销与数据

使用 Android 原生 View / Canvas，不使用 WebView、Compose、联网 SDK 或常驻动画。Root / Shizuku 各自只启动一个采集进程，不为每次采样执行 shell。录制流式写 CSV，实时 FPS 使用固定数组；移除录制期间的 Low / 分位数扫描和周期全量摘要。停止并关闭采集器后，后台流式分析原始文件并显示进度。GPU 等失败节点正常采集时退避 30s，手动诊断强制重新读取；悬浮窗绘制最多约每 500ms 一次。历史索引每 128 行记录偏移，读取使用 64KB 缓冲，图表只保留绘制用的极值包络。

APK 文件小不代表运行内存同样小。目前没有实机 CPU、GPU、内存、功耗对比结果，也不承诺“零开销”。可应用低开销预设、减少悬浮窗指标或隐藏悬浮窗。提高帧采样间隔可能漏掉高帧率场景的有限缓冲，应同时检查帧读取状态。

记录写在应用私有目录，不联网、无自动过期、无数量收费限制。原始文件每 2 秒刷盘，停止时关闭文件后计算统计。摘要使用临时文件和原子替换；统计失败保留原始数据，历史可重试恢复。强制结束可能损失尚未刷盘的尾部数据，未完成尾行不纳入统计，已落盘完整内容仍可查看。卸载会删除私有记录，请先导出。

## 源码与构建

`app/` 是标准 Android Studio 项目：AGP 8.7.3、compileSdk / targetSdk 35、minSdk 26、Java 8、Shizuku API 13.1.5。打开源码目录后可用 Android Studio 构建。

也可不启动 Gradle，使用 `build-local.py`：需要 Java 17、Android SDK platform 35 / build-tools 35.0.0、ECJ 3.38.0。设置 `ANDROID_SDK_ROOT` 和 `ECJ_JAR` 后运行：

```sh
python3 run-tests.py
python3 build-local.py
```

`setup-toolchain.py` 可下载固定版本的 SDK 工具、ECJ 与依赖，安装所需的两个 SDK 包，不安装模拟器。纯 JVM 回归使用的 Android JSON jar 放在 `toolchain/test-deps`，仅用于测试，不打进 APK。

`deps/` 保留 Shizuku AAR/JAR 与 AndroidX annotation，源码与 APK 中包含相应许可证。`dev-signing/lightframe-test.jks` 为测试版公开开发密钥，密码 `changeit`，用于保持测试更新签名一致；正式发布应另建私有密钥。

本项目原创代码为 MIT 许可，Shizuku API 为 MIT，AndroidX annotation 为 Apache-2.0。参考界面不包含 RakkaRecorder 的程序代码、名称图标或视频资产。

0.2.4 的日志结论、1,760 项检查、编译及签名结果见 `docs/VALIDATION-0.2.4.md`；新版安装启动、授权流程、前台图层选择、触摸交互和实际资源开销均需实机验证。

## 版本发布与设备反馈

公开仓库为 [ggboy6666/LightFrame](https://github.com/ggboy6666/LightFrame)，安装包及源码在 [Releases](https://github.com/ggboy6666/LightFrame/releases)。既有版本使用独立版本标签；后续提交版本修改并逐个推送对应 `vX.Y.Z` 标签，会执行测试、构建及发布工作流。也可在 Actions 的发布流程输入已有标签补跑；不要一次推送超过三个版本标签，以免 GitHub 不创建推送事件。

设备问题通过仓库的反馈表单提交。每月 1 日 20:00（北京时间）的 GitHub 工作流汇总上个月新增反馈、评论和按机型归组的累计问题；GitHub 排队可能延迟执行，报告保存在 `docs/feedback/`。归组结果用于安排真机复现、修复与下一版适配；未经复测不会标记“已适配”。详细口径见 [反馈工作流](docs/FEEDBACK-WORKFLOW.md)。这些工作在仓库执行，APK 没有加入评论收集或联网反馈功能。
