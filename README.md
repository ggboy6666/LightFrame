# 轻帧 LightFrame 1.0.0

原生 Android 性能工具，提供完整版与精简版。完整版保存原始采样与逐帧记录，在停止后计算统计；精简版只显示实时指标，不创建记录文件。两个版本使用不同包名，可以并存。浅紫色界面参考用户提供的 RakkaRecorder 录屏，程序为独立实现。

## 安装与使用

1. 支持 Android 8.0 及以上。完整版安装 `LightFrame-1.0.0-full.apk`；从旧轻帧覆盖更新时保留记录，请先停止采集，不要卸载旧版。精简版安装 `LightFrame-1.0.0-lite.apk`。
2. 未 Root 的手机 / 平板打开“采集授权向导”，安装并启动 Shizuku，再返回轻帧授权。支持的设备可通过 Shizuku 无线调试配对启动，日常使用不需要电脑；重启后需重新启动 Shizuku。已有 Root 可直接选择 Root，Sui 通过相同授权接口使用。本版没有内置无线 ADB 配对器。
3. 按需授予通知与悬浮窗权限。目标包名可以留空自动选择，也可填写以固定游戏。
4. 完整版点击“开始记录”，结束后“停止并保存”，等待统计完成；精简版点击“开始显示 / 停止显示”，没有记录页面。通知也可暂停、隐藏或停止。
5. 设置里可以手填采样间隔、选择夜间 / 日间 / 跟随系统，分别设置悬浮窗背景与文字的颜色和不透明度。外观即时生效；采样间隔与 FPS 开关在下次采集生效，GPU 工作追踪开关也可在采集中关闭。

默认帧读取 500ms、硬件 2000ms、温度 5000ms、悬浮窗每秒更新，GPU 系统工作追踪默认关闭。已有手填间隔会保留；升级后可应用新版“低开销预设”。采样与逐帧文件错开约 2 秒的周期刷新，常规每轮最多刷新一份有新数据的文件；缓冲满时仍会写出，暂停和停止时完整刷新。停止关闭文件后，再计算 Low、分位数及全记录摘要。

帧 / 硬件 / 温度间隔分别允许 50–5000、100–60000、500–60000ms。间隔越小，变化越细，读取开销越大；较大间隔可能漏掉短时峰值。系统只保存有限的呈现帧，FPS 读取会根据实际刷新周期自动缩短过大的间隔以保留余量，设置值是正常周期上限。读取本身太慢时主动延后，不补跑积压任务，真实缓冲缺口仍如实标记。温度通常变化较慢，建议 2–5 秒。

悬浮窗可以选择 1–12 个指标，拖动移动、双击打开、长按隐藏。背景和文字分别支持 RGB 颜色与 0–100% 不透明度，0% 完全透明、100% 完全不透明。隐藏悬浮窗仍继续采集；停止必须使用通知或主页的停止按钮。

## 查看与删除记录

- 完整版打开记录后，在 FPS、CPU、频率、GPU、RAM、功耗、温度、电池标签查看曲线。
- 单指横向滑动查看原始数值，双指缩放或平移，上下滑动页面；双击同一位置复位。各图共用时间区间。点选或滑动不会自动滚到详情，点击“查看所选时刻详情”才滚动。
- 时间浏览仅在有数据的曲线、采样明细或逐帧页显示；全记录概览及无数据页不显示。
- “跳到准确时刻”支持经过秒数、分:秒.毫秒、时:分:秒.毫秒，或当地日期时钟。显示最近原始采样及时间差，不插值造值。“选择起止区间”筛选全部图表与明细。
- 原始采样和逐帧数据每页 50 行，支持前后翻页及按序号跳转。原始字段可复制，上一条 / 下一条不会越过所选区间。
- “查看区间全部统计 / 缺失原因”读取区间内全部有效行。长记录的曲线使用极值包络减少绘制量，原始文件和全量统计不删减。
- 右上角导出完整 ZIP、全部或区间 CSV、单条曲线 PNG。旧记录可从原始 CSV 恢复统计；旧版从未采集到的数据不能补回。
- 记录列表点击“删除”进入勾选模式：“全选”再次点击即“全不选”，支持“反选”和批量删除。长按单条记录也可进入选择。删除前确认，正在采集或分析的当前记录受保护；删除原始数据后无法在本机恢复。

## 指标来源

| 指标 | 来源与含义 |
| --- | --- |
| FPS | SurfaceFlinger 指定图层的实际呈现时间，在有效的近 1 秒窗口计算。首次进入、换源或缺口后先收集有效窗口，避免假爬升。 |
| 帧时间 / 逐帧时间 | 相邻捕获呈现时间差；缺失帧无法重建，不把缓冲缺口伪造为单条长帧。 |
| 1% / 0.1% Low | 停止后计算最慢 1% / 0.1% 捕获帧间隔的均值倒数，使用有界直方图近似。 |
| FPS P1 / P5 / 标准差 | 有效 FPS 采样的百分位与波动，和逐帧 Low 是不同口径。 |
| 长帧 / 严重长帧 | 新记录按当时实际屏幕 / VSync 周期的 1.5 / 3 倍估算，不设置目标帧率或固定刷新率上限。预算未知或刷新率切换的歧义间隔不参加长帧判断，但原始帧间隔仍保留。游戏主动限帧也可能超过显示预算，因此不能当作游戏卡顿次数。旧记录保留旧口径。 |
| CPU / 频率 | `/proc/stat` 系统总体使用率，cpufreq policy 频率，最多 16 个策略；策略不是物理核心编号。 |
| GPU 负载 / 频率 | 优先读取厂商可访问的只读节点。显式开启 GPU 工作追踪后，节点不可用时尝试已报告工作区间并集忙碌率及最新频率事件。不能用温度 / 频率猜使用率。 |
| 温度 | 明确的 CPU / GPU / SoC 热区；电池温度独立，不替代 CPU / GPU。 |
| RAM | 系统 MemTotal − MemAvailable，不是游戏独占内存。 |
| 电流 / 功率 | 电池接口电流及电压，功率为电池侧估算；充电时不代表总输入功率或芯片功耗。 |
| 网络 | 非 lo 接口收发汇总；VPN 等场景可能重复计入。 |
| 轻帧 CPU / RSS | 应用与独立采集进程之和，CPU 为单核当量，RSS 包括共享页。不包含系统处理请求、GPU 合成或 Perfetto 系统服务的开销，不等于完整增量影响。 |
| 数据距今 | 硬件 / 温度 / GPU 实际数据年龄，用于识别重复显示的较慢值。 |

空值显示 `—`，CSV 留空，不自动补零。无效或过期窗口的 0 FPS 不计入均值和最低值；真实低帧数、逐帧长卡顿仍保留。旧记录只有同一行能证明 FPS 窗口无效时才排除 0。百分比轴为 0–100%，越界原始值有标记；FPS 轴覆盖实际峰值。图表文字与触摸坐标按窗口实际尺寸绘制，支持手机、平板、横屏和分屏。

## 高负载开销与 GPU

用户反馈旧低开销预设仍在负载突增时卡顿，1.0.0 做了以下变化：

- 默认关闭额外 GPU 系统工作追踪，新低开销预设也会关闭该项；可访问的直接节点仍读取。
- 缓存悬浮窗文本，每秒更新，减少指标；主页离开后停止界面刷新。
- 节点读取重用缓冲，帧解析用原始数组扫描与排序去重，减少正则与对象分配；保留完整帧环。
- 逐帧 CSV 重用行与字符缓冲，周期刷新错开，避免每轮同时刷新两份文件；原始字段与逐帧数量保持一致。
- 采样、采集器、系统读取和历史文件任务使用后台线程优先级，慢请求主动退避。
- 精简版跳过记录创建、CSV 写入、摘要及分析，仅维护实时显示必要的帧状态。

记录中的“采集请求耗时”只计到采集器返回；“上一轮总耗时”和“上一轮记录处理耗时”来自前一轮完整处理，包括实际写入和当轮文件刷新，附有那一轮开始的单调时钟时间。它们在下一条采样保存，首次、暂停恢复及不适用的精简版记录耗时为空；停止前最后一轮可能没有下一条采样，不能把它们当作全部逐轮计时，也不能将记录处理时间都解释为纯磁盘耗时。

持续 FPS 读取仍会调用系统合成器；悬浮窗仍是一层需要合成的窗口。因此不能承诺零开销，也不能仅凭采集器平均 CPU 低判断高负载时没有影响。可分别关闭 GPU 工作追踪、隐藏悬浮窗、关闭 FPS，再在同场景比较；精简版去除了记录写入，但不会消除 FPS 读取或悬浮窗合成成本。实际测试与限制见 [1.0.0 验证](docs/VALIDATION-1.0.0.md)。

已验证的 vivo PA2573 / Android 16 未 Root，直接 GPU 节点受限，Shizuku Shell 可以读取系统工作及频率事件。该通道约 8 秒返回一个延迟的 1 秒窗口，非连续覆盖每秒，可能漏掉短峰值；记录显示实际窗口与年龄。保护内容可能未报告，不完整追踪、丢失或时钟错误继续为空。追踪有时间、文件、缓冲上限；关闭、暂停、息屏或停止会取消自身追踪。原始 GPU 缺口与时钟修复见 [0.2.6 验证](docs/VALIDATION-0.2.6.md)。

设置可指定 `/sys/` 或 `/proc/` 内的 GPU 节点及固定图层；路径只读，不修改系统频率、电压、温控或游戏性能模式。Shizuku 不会把设备变为 Root，液冷也不会自动解锁超频。本机没有已验证的无 Root 超频接口。

## 版本更新与构建

设置提供“检测版本”和“一键更新”。只在用户主动操作时访问 GitHub，匹配完整版 / 精简版的正式 APK，校验大小、SHA-256、包名、版本和签名；采集期间停止更新。Android 仍需确认安装，首次可能要求允许轻帧安装更新。

源码是标准 Android 项目：Java 8，minSdk 26，compile / targetSdk 35，Shizuku API 13.1.5。也可用官方 SDK、ECJ 与 `build-local.py` 构建双包：

```sh
python run-tests.py
python build-local.py --variant all
python scripts/package_source.py
```

正式构建要求 `LIGHTFRAME_SIGNING_KEYSTORE`、密码环境变量及完整版的 `LIGHTFRAME_SIGNING_LINEAGE`，私钥在仓库外。`--development-signing` 只生成带 `-dev` 后缀的本地开发包，无法覆盖使用新正式证书的应用。`setup-toolchain.py` 准备工具与依赖，测试 JSON jar 不打进 APK。

完整版保留旧包名。Android 9+ 通过签名轮换使用新私有证书并保留原数据；Android 8.0/8.1 为覆盖旧测试版仍使用旧兼容签名，该旧测试私钥曾公开，不能把它当作防伪保证。精简版从首次安装就使用新私有证书。新私钥、密码不在源码包；仓库中的旧开发密钥仅为兼容历史版本保留。

原创代码 MIT，Shizuku MIT，AndroidX annotation Apache-2.0，包含相应许可证。没有加入 RakkaRecorder 代码、图标或视频资产。
