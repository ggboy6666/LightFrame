# LightFrame 1.0.1 验证范围

检查日期：2026-11-08。本次为 1.0.0 的修复更新，完整版和精简版均为 1.0.1 / code10。没有修改系统频率、温控、采样默认间隔或 GPU 工作追踪默认开关。

## 修复依据

| 问题 | 原因与修改 | 验证边界 |
| --- | --- | --- |
| 首次 Shizuku 授权后仍走旧模式 | 首次授权成功回调未保存采集模式；统一成功处理，同时更新主页下拉框，保留用户正在填写的记录名称与目标包名。拒绝授权保持原模式，忽略销毁后的回调。 | 真机首次授权界面仍待复测。 |
| 暂停 / 息屏恢复后的 CPU 与网速失真 | 原采集器保留暂停前的累计计数，将跨暂停区间的增量当作恢复后的新读数；暂停时清除 CPU 与网络基线，恢复首轮留空，下一轮使用新基线。 | 不重建缺失数据，不把首轮空值补零。 |
| 图表手势中旧结果覆盖视图 | 改变时间区间时未使在途历史请求失效；现在立即作废并取消旧请求，松手后仍只重新读取一次。 | 此次未在手机或 Pad 上复测手势。 |
| 精简版诊断分享失败 | 导出 URI 使用了完整版固定 authority；改为当前应用包名，与两个版本各自的 Provider 声明匹配。 | 此次未调用 Android 实机分享面板。 |
| 重复编译数值解析正则 | 复用三个只读 Pattern，每次调用仍创建独立 Matcher；表达式与解析语义保持一致。 | 这是解析路径的小幅优化，没有游戏性能改善率。 |

## 仓库与设备状态

检查时 GitHub 最新正式版为 1.0.0。[上月反馈报告](feedback/2026-10.md) 已由月度任务生成，设备反馈与评论均为 0；当前公开 Issues 也为空。因此没有依据宣称增加了新机型适配。每月统计继续在仓库执行，不加入 APK。

本次电脑未连接 Android 设备，未执行安装、在线升级或游戏测试。1.0.0 的真机结果见 [前版验证记录](VALIDATION-1.0.0.md)，不能冒充本版实测。用户此前报告的高负载游戏顿挫仍待同场景对比，不能据本次源码修复和离线检查宣称已经解决。

## 本版验证

- 重新编译并运行完整离线回归，21 组、5863 项检查通过；并发检查数量可能随调度略有变化。
- 月度反馈脚本的 37 项测试通过。
- 使用真实 `CoreSampler` 与 Android 端点替身进行 11 项暂停恢复行为验证：恢复首轮 CPU、RX、TX 留空，下一轮使用恢复后的计数差；同一用例对修复前版本失败。这些项目外检查不是 Android 实机数据。
- 从实际授权和时间浏览方法体、回调保护条件提取的 JVM 模拟验证 38 项通过，覆盖原模式为 basic / root、拒绝授权、销毁后的回调和旧历史请求。它不代替 Android 权限界面与触摸事件验证。
- 本机完整版与精简版均已成功编译、完成默认 SDK 的签名验证；没有更换正式签名配置。正式下载以 [v1.0.1 发布资产](https://github.com/ggboy6666/LightFrame/releases/tag/v1.0.1) 及随附 SHA256SUMS 为准，不混用本机与 CI 封装的整包摘要。

发布流程会再次运行完整回归，并分别生成 Full / Lite APK、完整源码与校验摘要。旧版标签、安装包、原始记录和月度反馈均保留。新的云端资产发布后另行核对，不将发布前的本地检查表述为真机更新成功。
