# LightFrame 0.2.6 GPU 缺失与历史曲线修复

日期：2026-10-02。用户报告 0.2.5 的 GPU 历史有长段空白。通过设备上的完整 ZIP 导出读取原始记录，未改写或删除原记录。设备为无 Root vivo PA2573 / Android 16，使用已授权的 Shizuku Shell。

## 原记录证据

记录时长 1556.409 秒、5701 行采样、180745 条捕获帧间隔；帧 / 硬件 / 温度间隔为 250 / 1000 / 5000ms。

- GPU 忙碌率和频率各有 1376 行有效、4325 行缺失，有效行占 24.14%。这些行重复保存缓存值，只有 43 个不同 GPU 测量窗口，不能把行数当成独立捕获次数。
- 缓冲完整性错误出现在 3204 行，按状态变化可区分 29 个错误状态段；时钟错误出现在 112 行、1 个状态段。CSV 没有失败捕获编号，状态段不是精确的追踪次数。
- 最长缺失约 391.972 秒，前后有效值相隔 392.502 秒；期间 1434 行 CPU 全部有效、FPS 有效 1432 行、暂停 0 行。录制没有整体中断。
- 旧版把六种缓冲错误合并为一句话，不能从该记录确认全部都是中央缓冲容量不足。补丁、ABI 和生产端共享内存丢失也会产生此提示。

原始诊断、完整记录、截图和追踪仅保存在本机项目外，未加入公开源码、安装包或反馈统计。

## 修复

Perfetto `BuiltinClock` 编号与 Linux `clockid_t` 不同：MONOTONIC=3、MONOTONIC_COARSE=4、MONOTONIC_RAW=5、BOOTTIME=6。0.2.5 错把 4 当成 RAW，导致粗时钟抖动触发映射变化检查，也可能移动统计窗口。0.2.6 用命名常量和 RAW=5；真实 RAW 映射不连续、缺失、损坏追踪仍拒绝数值。[官方时钟协议](https://github.com/google/perfetto/blob/v49.0/protos/perfetto/common/builtin_clock.proto)

中央缓冲初始由 512KiB 增至 2MiB，仅开启 GPU 工作与频率两个事件，保持 8 秒捕获。明确出现 `chunks_overwritten`、`bytes_overwritten` 或 `chunks_discarded` 正值时，下一次扩至最高 4MiB，等待 1 秒；到达上限继续失败则退避 30 秒。SMB / 补丁 / ABI 等单独错误不扩容；混合错误中有容量证据也只尝试一次扩大。失败追踪继续为空，新值必须来自独立完整追踪。暂停保留已确认容量，取消的旧任务不能改变新状态。

错误现在分别保存六种非零计数：上述三种容量计数，以及 `patches_failed`、`abi_violations`、`trace_writer_packet_loss`。多缓冲计数汇总、重复累计快照不重复加计，异常大计数按有界下限报告。[官方缓冲统计协议](https://github.com/google/perfetto/blob/v49.0/protos/perfetto/trace/trace_stats.proto)

文件上限 8MiB，保留最大缓冲之外的服务包余量；单包上限 1MiB、输出上限 128KiB、进程最长 18 秒。完成、最终刷新、全部 CPU 结束统计和无丢失检查保留。仅清理本次创建的准确文件名与子进程。

历史曲线原先把桶内缺失标记放在桶尾，可能断开连续值或跨缺失连线。现在按原始有效区段和缺失时刻绘制，极值保留原行顺序，包括相同时间戳；全视图最多 9003 个绘制点。原始 CSV、全量统计和精确采样选择不变；真实 GPU 零保留。旧版未取得的值无法重建。

本机最终代码的 JVM 回归全部通过，本次运行报告 2706 项检查（并发生命周期检查数量随调度略有变化）。包括不同原始缺失 / 暂停拓扑、完整统计、COARSE 抖动与 RAW 真正跳变、六种丢失计数、扩容与精确重试边界、上限退避、恢复必须重新验证、文件限制和取消清理。Android SDK 编译、v2 / v3 签名通过；包版本 0.2.6、版本码 8，沿用原签名覆盖安装。
